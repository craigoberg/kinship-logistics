## Learning layers (spine)

1. **Why the app behaves** — High Trust, Competency, RYGE, Duty of Care, Big Red  
2. **People in motion** — arrival methods, on-bus handover, late/missing timers, rolls  
3. **Care of place** — walkarounds / safety checks before open  
4. **Care of the day** — Day Centre + meal + checkout → bus  
5. **Care of exceptions** — Hub lanes, update cadence, Council email, Big Red → verbal → receipt  
6. **Care of the outing** — safe venue → Event Manage → Deliver → HOME (same concepts, different door)  
7. **Care of the overnight** — hotel last, evening/morning roll calls  
8. **Care of the paper trail** — Trip Report + Day Centre report (not NDIS pack today)

**YADA → Kinship bridge (say once):** same duty of care; Kinship adds shared RYGE language, receipts, and who has the person now.

## A — Mindset & map (~25 min)

- **High Trust / Competency**  
  - *Talk:* Competent people + receipts. Empty checklists = trust until risk says otherwise. Green moves fast; Red stops or gets a manager.

- **RYGE** — shared language (colour = urgency; Hub tab = topic)  
  - *Talk:* Colour is not which Hub tab. Tab is person vs thing vs expiry.

### Typical RYGE events

| Colour | Typical examples | What the system expects |
|--------|------------------|-------------------------|
| **Green** | Scuff/graffiti; cosmetic dent; minor notice that does not change today’s plan | Log it; low urgency; still in Hub until closed |
| **Yellow** | Lift needs documented two-person workaround; late bus still expected; cert/venue inside grace; meal SFH gap already manager-approved | Continue with named workaround; promote to Red if workaround fails |
| **Red** | Cannot safely open Centre/venue; critical vehicle fault with no workaround; welfare needs manager *now*; missing past Red threshold | Stop or verbal/manager path + receipt; may hard-block Open/Close |

- **Duty of Care chain (whiteboard)**  
  Home → Bus → Centre/Venue → Bus → Home  
  - *Talk:* Handover is on the bus / at transfer — not waved at the door.

- **Surfaces map**  
  Dashboard · Day · Manifest · Events (Manage / Deliver) · Hub · Staff/Admin  
  - *Talk:* Dashboard = today’s pulse. Hub = work queue.

- **Foreshadow Hub heartbeat (one sentence)**  
  - *Talk:* Open Active Hub work needs regular updates unless you Defer — we practise that after the Centre day.

- **Big Red Button** — introduce here (omnipresent watchful control)  
  - *Talk:* Always visible. Not a toy. Same watchfulness all day. We’ll push it once later with fake data.

### Big Red lanes — when to push / when not

| Lane | Use when | Not for |
|------|----------|---------|
| **Human / Operational** | Person welfare, injury, dispute, operational Red needing manager path | Ordinary walkaround tick fails (use Log issue / venue issue) |
| **Equipment / Asset** | Bus/lift/equipment fault that needs incident-style capture | Cosmetic Green that belongs in Maintenance via walkaround |
| **Health & Safety** | Infectious exclusion, lockdown / do-not-open, drill/live emergency | Free-text “something feels off” that is really Human or Asset |

- **Alpha framing**  
  - *Talk:* TEST isn’t real clients. Push buttons. Break things. Better here than field silence.

## B — Clients lite + how people are expected to arrive (~30 min)

- Open a participant: identity, schedule → Centre day expectation, diet/allergy chips (lite)  
  - *Talk:* Floor sees chips; office owns the record.

- Fred: daytime meds exist — touch once in C, not deep rounds.

- **Arrival methods that seed Manifest** (do this before Manifest)  
  - **Bus Run 1 / Run 2 (Rx)** — planned on a run → appears on Manifest  
  - **Self** — not on the bus list; still expected on the floor Check-In  
  - *Talk:* Manifest only picks up people planned on a run. Self-arrivals skip the bus but still Check-In.

- **Foreshadow clocks**  
  - *Talk:* Each expected person has an expected time. Unless deferred, late becomes missing — we show that after 09:00 Check-In.

- **Whiteboard / screen exercise**  
  Pick 4–6 clients for today → mark each R1 / R2 / Self  
  - *Talk:* This list is what Mark will see on the morning run card.

- Optional: each person adds one simple participant (name + basics).

- Do **not** open Centre yet — next block starts the bus while Centre opens in parallel.

## D — Hub + Dashboard + update cadence + Council (~40 min)

- Use issues created in C (toilet / walkaround / odd incident)  
  - *Talk:* Hub is the queue; Dashboard is the pulse. Don’t confuse them.

- **Three streams** (+ Health & Safety beside)  
  Human = people · Maintenance = things/places · Compliance = dates/certs  
  - *Talk:* Any stream can be Green/Yellow/Red. Pick tab by subject; RYGE for urgency.

- **Active / Deferred / Resolved**  
  - *Talk:* Active = needs attention now. Deferred = owned, parked to a date. Resolved = loop closed with why.

- **Update cadence (main teaching)**  
  - *Talk:* Open Active items need regular Log Notes or they show Update Due / Stale. Unless you Defer, the system expects a heartbeat. Alpha managers: Log Note is how the office stays in the story.

- **Practice**  
  - Progress/resolve the toilet (Maintenance)  
  - Log Note with next action on a Human or Maintenance card  
  - Optional second note to show “fresh” vs stale

- **Council (office only)**  
  - Generate/send email from the workflow  
  - *Talk:* Email goes out; ongoing updates still live in Hub — council is not a second brain.

- **Big Red 30-sec reprise**  
  - *Talk:* Same three lanes from A — full push in Block I if time.

## E — Day trip concepts (~25 min)

- Same custody + RYGE + walkarounds — **different arrival point** (venue, not Centre)  
  - *Talk:* Day Centre with a different front door.

- **Create a venue** fit for people with disability / access needs  
  - Complete baseline / safety fields → sign-off so it’s bookable  
  - *Talk:* If it isn’t safe to consider, don’t put it on an itinerary.

- **Day-trip chain**  
  Manifest IN → venue open inspection → programme (including meals) → checkout → HOME

- **Manage** = office plan · **Deliver** = field day  
  - *Talk:* “Run this event” is the handoff between them.

Venue creation may finish at end of E or open F.

Buffy and Michelle each create (or pair then swap):

3. Roster from existing clients (R1/R2/Self as relevant)  
4. Itinerary + meal stop  
5. **Costs / income–expense / balance sheet** — open and walk the money  
6. Confirm / ready for Deliver  

- *Talk (costs):* Office honesty before Confirm — know the balance story.

## G — Event Deliver (~40–45 min)

SIM = event date morning

1. Manifest IN (or self) → Check-In  
2. Open location walkthrough + PIN  
   - *Talk:* Ordinary walkthrough fails → Log Venue Issue — not global Big Red.  
3. Programme + meal on itinerary  
4. Check-Out → HOME Manifest → close day  

Optional: fail one open tick → Yellow continue with workaround vs Red verbal — pick honestly.

- *Talk:* Same custody arrows as the Centre morning — say them out loud.

## H — Multi-day extensions (~35–40 min)

- **Hotel** venue required for overnight; hotel stop **must be last** on that day’s itinerary  
  - *Talk:* Sleep place ends the day so evening roll has a home base.

- **Roll calls**  
  - Evening roll (non-final nights) — account before sleep  
  - Morning roll (Day 2+) — account before you move the group  
  - *Talk:* Defer-all exists for real delays — still a receipt, still a next time.

- Day close gates; Day N+1 blocked while Day N open  
- Place-to-place hops via Manifest  

**Short practice:** SIM Day 1 evening roll → close day → SIM Day 2 morning roll → point at next venue.  
Full multi-day build optional if time; concept + one roll cycle is enough.
